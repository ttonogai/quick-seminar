# ケース記録 ハンズオン用サンプルデータ

「ケース記録：回答案と記録ドラフトを同時生成」シナリオ（フロー型）で使うサンプルデータです。

## 想定シナリオ

情報システム部のヘルプデスク課が、社員からの問い合わせを CRM（チケット管理システム）に**1 件ずつ手で記録**しています。1 件あたり 5〜10 分かかり、対応そのものより記録に時間を取られている状態です。しかも記録の粒度が担当者ごとにばらついており、後から検索しても使えないという問題があります。

このシナリオでは、**問い合わせ本文を貼るだけで「類似ケース → 回答案 → 記録ドラフト」が同時に出てくる**フローを作ります。

> データはハンズオン用に生成した**サンプル（フィクション）**です。

## 前提：CRM 製品を特定しない設計にしています

`ケース項目定義.csv` は特定の CRM 製品に依存しない汎用の項目セットです。実際に使うときは、この CSV を自社の CRM から出力した項目定義に差し替えれば、そのまま動きます。Salesforce・ServiceNow・Zendesk・Jira Service Management など、製品を問いません。

## ファイル一覧

| ファイル | 役割 | 内容 |
|---|---|---|
| `ケース項目定義.csv` | 出力フォーマット定義 | 16 項目の型・必須・選択肢・記入ルール |
| `対応記録の書き方ガイド.md` | 記載ルール | 優先度判定基準・良い例と悪い例・禁止事項・聞き返し方 |
| `過去ケース履歴.csv` | 類似検索用 | 3 ヶ月分の対応済みケース 28 件 |
| `問い合わせ本文サンプル.md` | 入力用 | フローに貼り付ける問い合わせ本文 4 パターン |

## 列の説明

### ケース項目定義.csv

| 列 | 説明 |
|---|---|
| 表示順 | CRM の入力画面での並び順 |
| 項目名 / 項目API名 | 日本語ラベルと API 名 |
| 型 | テキスト（文字数制限）／選択リスト／数値／日時 |
| 必須 | 必須／任意 |
| 選択肢 | 選択リストの場合の候補値。`/` 区切り。**この値以外を使ってはいけません** |
| 記入ルール | その項目の書き方 |

### 過去ケース履歴.csv

`ケース番号` `受付日時` `依頼者部門` `カテゴリ` `サブカテゴリ` `優先度` `発生システム` `原因区分` `件名` `対応内容` `解決策` `再発防止策` `対応時間_分` `ステータス` `担当者`。すべての選択リスト項目は `ケース項目定義.csv` の選択肢に収まっています。

## このデータに仕込んである「気づき」

1. **同一事象の 3 回発生**：経費精算システムの SSO 認証エラーが `CS-2026-0412`（4/2）・`CS-2026-0417`（4/14）・`CS-2026-0522`（5/6）と 3 回発生しています。書き方ガイドに「3 回以上発生している場合は再発防止策として FAQ 化または恒久対策を必ず記載する」とあるため、サンプル 1 を入力すると**FAQ 化の提案まで出てくる**のが期待される挙動です。
2. **情報不足への対処**：サンプル 2（「印刷できません。急ぎです。」）では分類も原因も判定できません。書き方ガイドの「禁止事項」に「判断できない項目を空欄のままにしない／推測で埋めてはいけない」と明記してあるため、**「要確認」と聞き返し項目**が出てくるのが正解です。ここで推測して埋めてしまうフローは、実務では使えません。
3. **優先度の判定根拠**：サンプル 3（製造ライン停止）は判定基準の「事業活動が停止している」に該当し、優先度は「緊急」になります。類似ケース `CS-2026-0523` も製造ライン端末の起動不可で、予備機への切替という解決策が提示できます。
4. **ケースを分ける判断**：サンプル 4 は 1 通に「障害」と「権限申請」が混在しています。カテゴリは 1 つしか選べないため、**記録を 2 件に分ける提案**が出るのが望ましい挙動です。
5. **恒久対策の未実施**：`CS-2026-0631`（SSO 証明書期限切れ）と `CS-2026-0633`（バッチ異常終了）は、再発防止策に「（未実施）」と記録されています。トラブルシュートシナリオの過去障害レポートと同じ事象で、**未実施の対策が積み上がっている**構造になっています。

## 入力例（フローの実行時）

`問い合わせ本文サンプル.md` の各サンプルをコピーして貼り付けます。サンプル 1 → 2 → 3 の順に試すと、フローの挙動の違いがわかります。

## 実務で使うときの注意

CRM への**書き込みまで自動化するかは、慎重に判断してください**。このハンズオンは「ドラフトを生成して担当者がコピー＆確認して登録する」形にしています。記録内容の責任は担当者にあり、AI が削るのは入力の手間だけです。自動登録まで踏み込む場合は、権限設計と監査ログの検討が別途必要になります。
