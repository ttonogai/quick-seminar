# ナレッジ生成 ハンズオン用サンプルデータ

「ナレッジ生成：FAQ と運用手順書を自動作成」シナリオ（フロー型）で使うサンプルデータです。

## 想定シナリオ

情報システム部が、同じ問い合わせに何度も答えています。FAQ を整備したいという話は前から出ているものの、「履歴を分析して、頻出のものを選んで、FAQ の形に書き起こす」という作業に手が回りません。運用手順書も同様で、対応した本人の記憶の中にしか残っていない手順が数多くあります。

このシナリオでは 2 本のフローを作ります。

1. **問い合わせ履歴 → FAQ**：履歴を分類して、頻出上位を FAQ 形式で書き起こす
2. **対応記録 → 運用手順書**：1 件の対応記録を、他の担当者が再現できる手順書に昇華させる

> データはハンズオン用に生成した**サンプル（フィクション）**です。

## ファイル一覧

| ファイル | 役割 | 内容 |
|---|---|---|
| `../helpdesk/問い合わせ履歴.csv` | 分析元データ | **既存シナリオのデータを流用**。80 件の問い合わせ履歴 |
| `既存FAQ一覧.csv` | 重複判定用 | 公開済み FAQ 10 件 |
| `FAQフォーマット.md` | 出力フォーマット定義 | FAQ 1 件の構成 8 項目と記載ルール |
| `手順書フォーマット.md` | 出力フォーマット定義 | 手順書の全 9 章と記載ルール |
| `対応記録サンプル.md` | 入力用 | 手順書に起こす元ネタ 2 件（情報が欠けている） |

問い合わせ履歴は `data/helpdesk/問い合わせ履歴.csv` を使います。**社内ヘルプデスクシナリオと同じ Space を使い回すこともできます。**

## 列の説明

### 既存FAQ一覧.csv

| 列 | 説明 |
|---|---|
| FAQ番号 / カテゴリ / 質問 | 公開済み FAQ の識別と内容 |
| 対象者 | 全社員 / 管理者 |
| 公開日 / 最終更新日 | 更新が止まっている FAQ の判別に使う |
| 月間参照回数 | よく見られている FAQ の判別に使う |
| 関連手順書 | 対応する運用手順書の文書番号 |

## このデータに仕込んである「気づき」

### FAQ 生成フロー（問い合わせ履歴 → FAQ）

問い合わせ履歴 80 件のカテゴリ内訳は SaaS障害 26 / 端末障害 23 / ネットワーク 12 / アカウント 10 / 権限申請 9 です。

1. **既存 FAQ でカバーできていない頻出事象がある**：ドライバ不具合（外部モニターが映らない、カメラが認識されない）が 5 件、キャッシュ破損が 3 件ありますが、既存 FAQ にはありません。これらが `【新規】` として挙がるのが期待される挙動です。
2. **既存 FAQ があるのに問い合わせが減っていない事象がある**：VPN 接続（`FAQ-02`、月間参照 98 回）は履歴にも 5 件出ています。FAQ があるのに問い合わせが続いているので、**FAQ の内容不足か導線の問題**という指摘ができます。
3. **FAQ 化に向かないものが混ざっている**：`申請対応` が原因分類の最多（11 件）ですが、権限申請やアカウント発行は都度承認が必要で、利用者が自己解決できません。FAQ フォーマットの「FAQ 化に向かないもの」に該当し、**FAQ ではなく申請導線の整備が有効**という判断が出るのが正解です。ここを機械的に FAQ 化してしまうフローは実務では使えません。
4. **更新が止まっている FAQ**：`FAQ-04` `FAQ-07` は公開日から一度も更新されていません。棚卸しの対象として拾えます。

### 手順書生成フロー（対応記録 → 手順書）

`対応記録サンプル.md` の 2 件は、**わざと情報が欠けた状態**で書かれています。担当者本人には当然の情報が省略されているという、実際の対応記録によくある姿を再現しています。

- **記録 A（SSO 証明書更新）**：IdP 管理画面の場所、必要な権限、SP ごとの登録手順、作業中の利用者への周知、切り戻しの可否が不明
- **記録 B（ディスク領域不足）**：`df` を実行するサーバー、退避先ストレージ、手動再実行のコマンド、後続ジョブの実行順序の確認方法が不明

手順書フォーマットの第 9 章「【要追記】」に、これらが**質問形式で列挙される**のがこのフローの価値です。推測で埋めてしまうと、誤った手順書が流通します。

記録 B には「9月と1月にも同じことやってる」という記述があるため、第 7 章「注意事項・過去のトラブル例」に**再発の履歴と恒久対策の必要性**が書き起こされるのが望ましい挙動です。

## 実務で使うときの注意

**生成された FAQ・手順書は、そのまま公開しないでください。** 特に手順書は、`【要追記】` を埋める作業が本番です。AI が削るのは「体裁を整える時間」と「観点の抜け漏れを探す時間」であり、内容の正確性は実施者が担保する必要があります。

逆に言えば、`【要追記】` が多く出ることは失敗ではありません。**手順書の穴がどこにあるかが可視化された**ということです。
