# エラーコード対応集

文書番号: OPS-ERR-2026-01
管理部門: 情報システム部 システム運用課
最終更新: 2026年6月30日

このドキュメントは、社内システムで発生するエラーコードごとの症状・原因候補・一次対処・エスカレーション基準をまとめたものです。一次対応者はまずこの文書を参照してください。

## エスカレーション基準（共通）

以下のいずれかに該当する場合は、**一次対処を試みる前に**システム運用課長へ即時エスカレーションしてください。

| No. | 基準 |
|-----|------|
| E-1 | 全社または1部門全体が業務停止している |
| E-2 | 認証基盤（SSO・Active Directory）に起因し、複数システムに同時影響が出ている |
| E-3 | データの消失・不整合の可能性がある |
| E-4 | 外部取引先との連携（EDI・API）が停止している |
| E-5 | 同一エラーコードが 30 日以内に 3 回以上再発している |
| E-6 | 一次対処を 30 分実施しても復旧の見込みが立たない |

## ERR-DB-0412：ディスク領域不足によるトランザクション失敗

| 項目 | 内容 |
|------|------|
| 対象システム | 基幹業務システム、受発注システム（DB サーバー共用） |
| 重要度 | A（初動 30 分以内） |

### 症状
- 更新処理・登録処理でのみエラーになる（参照は正常）
- 夜間バッチが途中で異常終了する
- ログに `unable to extend table space` または `disk full` が出力される

### 原因候補（可能性の高い順）
1. トランザクションログの肥大化（ローテーション未設定・失敗）
2. 一時表領域の使用量が上限に到達
3. 大量データ投入によるデータファイルの急増

### 一次対処
1. `df -h` で対象ボリュームの空き容量を確認
2. 30 日以上前のアーカイブログを退避（削除ではなく退避）
3. 一時表領域の使用状況を確認し、不要セッションを解放
4. 空き容量 15% 以上を確保したうえで、失敗したトランザクションを再実行

### 切り分けのポイント
参照は正常で更新のみ失敗する場合、ネットワークやアプリではなくストレージ側が原因である可能性が高いです。

### 注意
**一時ファイルの削除だけでは再発します。** ログローテーション設定の見直しまで実施してください。

## ERR-DB-0517：デッドロック検出

| 項目 | 内容 |
|------|------|
| 対象システム | 基幹業務システム |
| 重要度 | B（初動 60 分以内） |

### 症状
- 特定の画面でのみ「処理に失敗しました」が表示される
- ログに `deadlock detected` が出力される
- 月初・月末の処理集中時に発生しやすい

### 原因候補
1. 月次バッチと業務画面からの更新が同一テーブルで競合
2. 長時間トランザクションの放置
3. 更新順序が統一されていないアプリ実装

### 一次対処
1. デッドロック相手のセッションを特定し、後発セッションを終了
2. 利用者に再実行を案内
3. 月次バッチと重なっている場合は、バッチ完了後の実行を案内

## ERR-AUTH-0271：SSO 証明書の期限切れ

| 項目 | 内容 |
|------|------|
| 対象システム | 全 SaaS（SSO 連携しているすべて） |
| 重要度 | A（初動 30 分以内） |

### 症状
- 複数のシステムで同時にログインできなくなる
- ログイン画面までは表示されるが、認証後にエラー画面に遷移する
- ログに `SAML signature validation failed` または `certificate has expired` が出力される

### 原因候補
1. IdP 側の署名証明書の有効期限切れ
2. SP 側に登録した証明書が古い（IdP のローテーション後に未更新）
3. サーバー時刻のずれによる有効期間判定の失敗

### 一次対処
1. IdP の署名証明書の有効期限を確認
2. 期限切れの場合は新しい証明書を発行し、各 SP に再登録
3. 反映後、代表ユーザーでログインを確認

### エスカレーション
**この事象は E-2（認証基盤起因で複数システムに同時影響）に該当します。** 一次対処と並行して、必ずシステム運用課長へ報告してください。

### 注意
証明書の有効期限は監視対象に含める必要があります。期限監視が未設定の場合、同じ事象が必ず再発します。

## ERR-AUTH-0288：アカウントロック

| 項目 | 内容 |
|------|------|
| 対象システム | Active Directory 連携システム |
| 重要度 | C（初動 240 分以内） |

### 症状
- 特定の利用者 1 名のみログインできない
- ログに `account is locked out` が出力される

### 原因候補
1. パスワード誤入力の連続（5 回でロック）
2. 古いパスワードを保存した端末やスマートフォンからの自動リトライ
3. 業務システムに保存された古い資格情報

### 一次対処
1. 本人確認のうえロックを解除
2. パスワードを再設定
3. **スマートフォンのメールアプリや別端末に古いパスワードが残っていないか確認**（ここを確認しないと再ロックします）

## ERR-APP-0533：コネクションプール枯渇

| 項目 | 内容 |
|------|------|
| 対象システム | 社内ポータル、受発注システム |
| 重要度 | B（初動 60 分以内） |

### 症状
- 画面表示が極端に遅い、またはタイムアウトする
- 一部の利用者だけが繋がる（繋がる人と繋がらない人が混在）
- ログに `connection pool exhausted` または `timeout waiting for idle object` が出力される

### 原因候補
1. アプリ側でコネクションを解放していない処理がある
2. 想定を超える同時アクセス（月初・キャンペーン時など）
3. DB 側の応答遅延によるコネクションの滞留

### 一次対処
1. アプリサーバーの現行コネクション数と上限値を確認
2. 長時間占有しているセッションを特定して解放
3. 改善しない場合はアプリサーバーを順次再起動（サービス断を最小化するため 1 台ずつ）

### 切り分けのポイント
「繋がる人と繋がらない人が混在する」のはプール枯渇の典型的な兆候です。全員繋がらない場合は別の原因を疑ってください。

## ERR-APP-0611：セッションタイムアウトの頻発

| 項目 | 内容 |
|------|------|
| 対象システム | 社内ポータル |
| 重要度 | C（初動 240 分以内） |

### 症状
- 作業中に強制ログアウトされる
- 入力内容が失われるという申告が複数

### 原因候補
1. ロードバランサのセッション維持設定が外れている
2. セッションタイムアウト値が業務実態と合っていない
3. ブラウザ側の Cookie 設定・拡張機能の影響

### 一次対処
1. 複数台構成の場合、セッション維持（スティッキーセッション）設定を確認
2. 特定利用者のみの場合はブラウザのキャッシュ・拡張機能を切り分け

## ERR-BATCH-0104：前提ジョブ未完了によるスキップ

| 項目 | 内容 |
|------|------|
| 対象システム | バッチ基盤 |
| 重要度 | B（初動 60 分以内） |

### 症状
- 後続ジョブが実行されずにスキップされる
- ログに `predecessor job not completed` が出力される

### 原因候補
1. 前提ジョブ自体が異常終了している（**まず前提ジョブのログを確認**）
2. 前提ジョブの処理時間が延び、後続の起動時刻を超過
3. ジョブ定義の依存関係の設定誤り

### 一次対処
1. **前提ジョブのエラーコードを特定する**（このエラー自体は結果であり、原因は前提ジョブ側にある）
2. 前提ジョブを復旧させてから、後続ジョブを手動実行
3. 当日の業務締めに間に合わない場合は業務部門へ連絡

## ERR-BATCH-0139：入力ファイル形式不正

| 項目 | 内容 |
|------|------|
| 対象システム | バッチ基盤 |
| 重要度 | C（初動 240 分以内） |

### 症状
- 取込ジョブが 0 件処理で正常終了、または即時異常終了する
- ログに `invalid record length` や `unexpected character` が出力される

### 原因候補
1. 文字コードの相違（UTF-8 と Shift_JIS の混在）
2. 改行コードの相違（CRLF と LF）
3. 項目数・桁数の変更が連携元で行われた

### 一次対処
1. 入力ファイルの文字コードと改行コードを確認
2. ヘッダー行の項目名・項目数を仕様と突き合わせ
3. 連携元の担当者に変更の有無を確認

---

## ERR-NET-0902：VPN トンネル確立失敗

| 項目 | 内容 |
|------|------|
| 対象システム | 拠点間 VPN、リモートアクセス VPN |
| 重要度 | A（初動 30 分以内。拠点全体が影響を受ける場合） |

### 症状
- 特定拠点から社内システムに一切アクセスできない
- ログに `IKE SA negotiation failed` が出力される

### 原因候補
1. 回線事業者側の障害・メンテナンス
2. VPN 機器のセッション上限到達
3. 事前共有鍵・証明書の不一致（設定変更後に発生）

### 一次対処
1. 回線事業者の障害情報を確認
2. VPN 機器のセッション数とリソース使用率を確認
3. 直近に設定変更がないか確認し、あれば切り戻しを検討

## ERR-NET-0915：DNS 名前解決失敗

| 項目 | 内容 |
|------|------|
| 対象システム | 社内ネットワーク全般 |
| 重要度 | B（初動 60 分以内） |

### 症状
- IP アドレス指定では繋がるが、ホスト名では繋がらない
- ログに `name or service not known` が出力される

### 原因候補
1. DNS サーバーの応答停止
2. クライアント側のキャッシュ不整合
3. VPN 接続時に配布される DNS 設定の誤り

### 一次対処
1. `nslookup` で社内 DNS への到達性を確認
2. クライアントの DNS キャッシュをクリア
3. VPN 接続時のみ発生する場合は、配布 DNS 設定を確認

## ERR-FS-0703：ディスククォータ上限到達

| 項目 | 内容 |
|------|------|
| 対象システム | ファイルサーバー |
| 重要度 | B（初動 60 分以内） |

### 症状
- 保存はできるが上書きに失敗する、または保存自体ができない
- ログに `quota exceeded` が出力される

### 原因候補
1. 部門割り当て容量の上限到達
2. ごみ箱・世代管理領域の肥大化
3. 個人フォルダへの大容量ファイル退避

### 一次対処
1. 対象共有フォルダの使用量と割り当て量を確認
2. ごみ箱・古い世代データの整理を依頼
3. 業務上必要な場合は容量追加を申請（申請から反映まで 3 営業日）

## ERR-MW-0450：ミドルウェアのメモリリーク

| 項目 | 内容 |
|------|------|
| 対象システム | 社内ポータル、基幹業務システム |
| 重要度 | B（初動 60 分以内） |

### 症状
- 稼働開始から数日経つと徐々に遅くなる
- 再起動すると一時的に改善する
- ログに `OutOfMemoryError` または GC の頻発が記録される

### 原因候補
1. アプリ実装上のオブジェクト解放漏れ
2. ヒープサイズ設定が業務量に対して不足
3. 特定機能の利用時のみリークが発生

### 一次対処
1. ヒープ使用量の推移を確認し、右肩上がりかを判定
2. 計画的な再起動で一時回避
3. 恒久対策はアプリ改修またはヒープ設定の見直し（ベンダー確認が必要）
