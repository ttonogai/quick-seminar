# トラブルシュート ハンズオン用サンプルデータ

「トラブルシュート：エラーから解決策を提示」シナリオ（エージェント型）で使うサンプルデータです。

## 想定シナリオ

情報システム部のシステム運用課が、社内システムの障害一次対応を担っています。障害が起きるとログを見ながら手順書を探し、原因を推定し、依頼者への案内文を書く——という流れを毎回人力でやっています。

このシナリオでは、エラーコード対応集・過去の障害レポートを Space に取り込み、**生ログを貼るだけで「原因候補・切り分け手順・依頼者への案内文・エスカレーション判定」が返ってくる**状態を作ります。

> データはハンズオン用に生成した**サンプル（フィクション）**です。

## ファイル一覧

| ファイル | 役割 | 内容 |
|---|---|---|
| `エラーコード対応集.md` | ナレッジ | 12 種のエラーコードごとの症状・原因候補・一次対処・エスカレーション基準 |
| `過去障害レポート.csv` | 実績データ | 直近 10 ヶ月の障害 12 件。原因・恒久対策とその実施状況を記録 |
| `障害ログサンプル.txt` | 入力用 | ハンズオンでチャット欄に貼り付ける生ログ 3 ケース |

## 列の説明

### 過去障害レポート.csv

| 列 | 説明 |
|---|---|
| 障害ID / 発生日 / 発生時刻 | 障害の識別と発生タイミング |
| システム名 | 対象システム |
| エラーコード | `エラーコード対応集.md` と対応。突き合わせの鍵になる列 |
| 事象 / 影響範囲 / 重要度 | 障害の内容と影響 |
| 原因 / 一次対処 | 実際の原因と、そのとき行った対処 |
| 恒久対策 / 恒久対策ステータス | 立てた対策と、実施済／未実施／検討中 |
| 対応時間_分 / 対応者 / 備考 | 対応工数と補足 |

## 3 つのログサンプルと、そこから見えること

### ケース A：夜間バッチが異常終了した
`ERR-BATCH-0104` が 3 行並んでいますが、**これは結果であって原因ではありません**。最初に出ている `ERR-DB-0412`（表領域の拡張失敗）が本当の原因で、後続 3 ジョブはその影響でスキップされています。対応集の ERR-BATCH-0104 の項に「まず前提ジョブのエラーコードを特定する」と書いてあるので、エージェントはそこを指摘できます。

さらに過去障害レポートを見ると、**`ERR-DB-0412` は 2025-09-12・2026-01-28・2026-06-03 と 3 回発生し、恒久対策「ログローテーション設定の見直し」がすべて未実施**です。エスカレーション基準 E-5（30 日以内に 3 回以上）には該当しませんが、「対策が放置されて再発している」という指摘が引き出せます。

### ケース B：朝からログインできない
`ERR-AUTH-0271`（SSO 証明書の期限切れ）です。複数部門・複数 SaaS で同時発生しているため、**エスカレーション基準 E-1（全社業務停止）と E-2（認証基盤起因）の両方に該当**します。一次対処より先に報告が必要なケースです。

こちらも過去に `INC-2026-0210` として発生済みで、恒久対策「証明書有効期限の監視項目追加」が未実施のままです。**同一原因の 2 回目**という指摘ができます。

### ケース C：午後になるとポータルが重い
`ERR-APP-0533`（コネクションプール枯渇）です。「遅い人と平気な人が混在する」という申告どおり、ログでは `portal-ap-01` が 50/50 で飽和している一方、`portal-ap-02` は 9〜11 しか使われていません。**単なるアクセス集中ではなく、ロードバランサの振り分けが偏っている**ことがログから読み取れます。あわせて 8.4 秒の slow query も出ており、DB 側の応答遅延がコネクション滞留を招いている可能性も指摘できます。

## 質問例（エージェントのチャットで）

- （`障害ログサンプル.txt` のケース A を貼り付けて）このログから原因を特定して、切り分け手順と依頼者への案内文を作ってください
- このエラーは過去に発生していますか？恒久対策は実施済みですか？
- この事象はエスカレーション基準に該当しますか？該当する基準の番号も教えてください
- 過去障害レポートから、恒久対策が未実施のまま残っている案件を一覧にしてください
- 直近 10 ヶ月で最も再発しているエラーコードはどれですか？根本原因を推定してください
- ERR-DB-0412 の一次対処を教えてください。再発を防ぐには何が必要ですか？
