# シナリオデータ 索引

ハンズオンシナリオごとのサンプルデータをディレクトリ単位で管理しています。**シナリオを追加するときは、この索引に 1 行足してください。**

各ディレクトリに `README.md` があり、ファイルの役割・列の説明・仕込んである気づき・質問例をまとめています。

## データ構成の規約

シナリオのデータは、役割ごとに次の 4 種類で構成します。**すべてを揃える必要はありません**が、この分類に沿わせると流用と差し替えがしやすくなります。

| 種類 | 役割 | 例 |
|---|---|---|
| ① ナレッジ（`.md`） | 根拠つき回答の source。規則・手順書・基準 | `就業規則.md` `エラーコード対応集.md` `保守契約条件.md` |
| ② 実績データ（`.csv`） | 集計・分析・類似検索の対象 | `勤怠実績.csv` `過去障害レポート.csv` `作業実績表.csv` |
| ③ 出力フォーマット（`.md` / `.csv`） | 生成物の型を固定する。**フロー型では必須** | `月次報告書テンプレート.md` `ケース項目定義.csv` `手順書フォーマット.md` |
| ④ 見本・入力サンプル | 文体の基準、または貼り付け用の入力 | `前月分_月次報告書.md` `障害ログサンプル.txt` `問い合わせ本文サンプル.md` |

加えて、ダッシュボード用に日次集計の `○○日次.csv` を置いているシナリオがあります（`helpdesk/チケット日次.csv`、`attendance/勤怠日次.csv`、`maintenance/保守訪問日次.csv`、`monthly-report/運用実績日次.csv`）。

### 型ごとに効くデータ

- **エージェント型**：①ナレッジ と ②実績データ が中心。回答の根拠を示せるかが価値になります
- **フロー型**：③出力フォーマット が生命線です。加えて ④見本（前回の完成品）を入れると、生成結果のばらつきが大きく減ります

## 入力サンプルの扱い

④のうち「貼り付け用の入力」は **Space にアップロードしません**。チャットやフローの入力欄に貼り付けて使うものです。該当ファイルは各シナリオページ内にも全文を掲載しているので、参加者はファイルを開かずにコピーできます。

- `troubleshoot/障害ログサンプル.txt`
- `case-record/問い合わせ本文サンプル.md`
- `knowledge-gen/対応記録サンプル.md`

## データを共用しているシナリオ

`knowledge-gen/` は分析元として `helpdesk/問い合わせ履歴.csv` を流用しています。同じ Space にまとめれば、「一次回答するエージェント」と「FAQ を作るフロー」を 1 つの Space で共存させられます。

同様に `troubleshoot/過去障害レポート.csv` と `case-record/過去ケース履歴.csv` は、同じ障害（SSO 証明書の期限切れ、ディスク領域不足）を別の切り口で記録しており、突き合わせると「恒久対策が未実施のまま再発している」構造が見えるようになっています。

## サンプルデータについて

すべてハンズオン用に生成した**フィクション**です。実在の企業・人物・金額とは関係ありません。
