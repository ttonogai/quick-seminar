# 社内ヘルプデスク ハンズオン用サンプルデータ

「社内ヘルプデスク：IT 一次対応を自動化しよう」シナリオ（エージェント型）で使うサンプルデータです。

## 想定シナリオ

約 250 名規模の企業の情報システム部ヘルプデスクを題材にしています。IT 問い合わせの一次対応・FAQ 回答・権限申請の案内・頻発事象の分析を扱います。

ヘルプデスクや IT サポートを事業として提供している場合は「自社のサポートデスク運用の効率化」に直結し、かつ業種を問わずどの顧客にも提案できるため、展開の主力になりうるシナリオです。

> データはハンズオン用に生成した**サンプル（フィクション）**です。

## 列の説明

### 問い合わせ履歴.csv

| 列 | 説明 |
|---|---|
| チケットID / 受付日時 | 識別と受付タイミング |
| 申告者 / 社員番号 / 部門 | 依頼者の情報 |
| カテゴリ | SaaS障害 / 端末障害 / ネットワーク / アカウント / 権限申請 |
| 端末管理番号 / 対象アプリ・サービス | 対象の端末とサービス |
| 事象概要 / 原因分類 / 対応内容 | 何が起きて、原因は何で、どう対応したか |
| 解決時間（分） / 対応者 / ステータス / 緊急度 | 対応工数と状態（緊急度は 業務停止 / 業務影響あり / 軽微） |

### 権限付与基準.csv

`職種コード` `職種名` `部門` `標準付与権限` `SaaSサービス` `権限レベル` `承認者` `承認フロー` `備考`。承認フローは「部長承認→情シス発行」が 62 件と大半で、機密性が高いものは「二重承認」「役員承認」「取締役会承認」「部長承認+CISO承認」に分かれています。

### チケット日次.csv

日次のダッシュボード用データです。`SLA達成` `FCRフラグ`（一次解決したか）`再発フラグ` `対応形態` `問合せソース` `要因区分` `顧客満足度` を含みます。

## このデータに仕込んである「気づき」

### 問い合わせ履歴.csv（80 件）

カテゴリ内訳は **SaaS障害 26 / 端末障害 23 / ネットワーク 12 / アカウント 10 / 権限申請 9** です。

1. **原因分類の最多は「申請対応」（11 件）**：権限申請やアカウント発行は障害ではなく手続きです。技術的な対処ではなく、申請導線の整備で減らせる領域だと分かります。
2. **ドライバ不具合が 5 件**：外部モニターが映らない、カメラが認識されないなど、同種の事象が繰り返し発生しています。FAQ 化の候補です。
3. **緊急度の分布は 業務影響あり 45 / 軽微 30 / 業務停止 5**：業務停止の 5 件に何が共通しているかを問うと、優先度判定の考え方が引き出せます。
4. **対象サービスの偏り**：Windows 11（10 件）、freee会計（8 件）、macOS（6 件）、VPN（5 件）、Salesforce（5 件）。上位に手順書の整備が集中していないかを確認できます。

### チケット日次.csv（2,000 件・2024-01 〜 2026-05）

- **SLA 達成 1,757 / 未達 243**（達成率 87.9%）。未達がどのカテゴリ・どの時期に偏っているかが分析できます
- **一次解決（FCR）あり 1,635 / なし 365**（81.8%）
- **再発あり 151 件**。再発率の高いカテゴリは恒久対策が必要な領域です
- カテゴリ最多は PCトラブル 455、以下 アカウント 366 / ネットワーク 256 / VPN 177
- 問合せソースは チケット 822 / チャット 580 / メール 312 / 電話 203 / 対面 83。電話と対面は記録が残りにくいチャネルで、記録漏れのリスクが議論できます

## 質問例（エージェントのチャットで）

- VPN に接続できません。Windows 11 です
- Slack のゲストアカウントを発行したいのですが、誰に申請すればいいですか？
- 先月から複合機の印刷が遅いという問い合わせが増えています。過去に同様の事例はありますか？
- 今月の問い合わせ履歴から、カテゴリ別の件数と対応完了率を出してもらえますか？
- 原因分類が「申請対応」の問い合わせを一覧にして、申請フローの改善案を提案してください
- 再発している事象を抽出して、恒久対策が必要な順に並べてください

## 関連シナリオ

- `../troubleshoot/`（トラブルシュート）— エラーログからの原因切り分け。一次回答より踏み込んだ障害対応
- `../case-record/`（ケース記録）— 対応内容を CRM 登録用に構造化するフロー
- `../knowledge-gen/`（ナレッジ生成）— **この `問い合わせ履歴.csv` を分析元として流用**し、FAQ を自動作成します
